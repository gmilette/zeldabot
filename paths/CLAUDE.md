- do not add comments

  This means no KDoc, no header blocks, no section banners, no restating what the
  next line does. Name things well instead. The same applies to text the code
  generates: reports, console output and HTML show numbers, not essays about
  methodology. Rationale that a reader genuinely needs goes in a markdown file, not
  inline.

  The only comment worth writing is one recording something the code cannot show:
  a non-obvious constraint, or why an obvious-looking alternative was rejected.
